# Padel Batumi Bot

Telegram-бот, который показывает свободные корты для падела в Батуми и даёт ссылку на бронирование.

Клубы: **Padel Port Batumi** (Padel Courts + Park Courts) и **Grand Padel Batumi**.

> Неофициальный проект. Не связан с Reservio и клубами. Данные берутся из публичного API страницы бронирования.

## Как работает

- Бот опрашивает публичный JSON:API Reservio `GET /v2/businesses/{businessId}/availability/booking-slots` по каждому корту параллельно.
- Результаты кэшируются в памяти на `CACHE_TTL_SECONDS` (по умолчанию 60 с). Одинаковые одновременные запросы схлопываются в один.
- «Игровой день» длится с 06:00 до 06:00, поэтому ночные слоты 00:00–01:00 показываются в предыдущем дне.
- Кнопка слота открывает список свободных кортов. Для каждого бот создаёт черновой заказ Reservio с выбранным временем и даёт ссылку на шаг времени этого заказа, где остаётся нажать «Continue». Ссылку сразу на оформление бот не даёт: без cookie Reservio показывает на ней 404. Ссылки кэшируются на 10 минут отдельно для каждого пользователя, частота нажатий ограничена.
- Бот работает только в личных чатах: ссылку на черновой заказ может открыть любой, кто видит сообщение. В группе бот предлагает написать ему в личку.

Клубы и корты описаны в `venues.yaml`. ID услуг можно получить так:

```bash
uv run python scripts/dump_services.py padel-port-batumi2
```

## Локальный запуск

```bash
cp .env.example .env         # вписать BOT_TOKEN от @BotFather
uv sync
uv run padel-bot
```

Посмотреть слоты без Telegram:

```bash
uv run python scripts/show_slots.py tomorrow e   # m=утро, a=день, e=вечер, w=весь день
```

Тесты и линт:

```bash
uv run pytest
uv run ruff check . && uv run ruff format --check .
```

## Мониторинг кортов

Вечерние корты разбирают заранее, а освобождаются они при отмене чужой брони. Бот может следить за этим сам.

- На экране дня кнопка «🔔 Следить» открывает сетку часов. Нажатие на час создаёт подписку на этот день и час, дальше на карточке переключаются «каждую неделю» или «только эта дата», длина до 3 часов (конец не позже 02:00), клуб и «1 или 2 корта в одном клубе с одним временем». `/subs` показывает подписки, `/watch` подсказывает, как создать новую. У одного пользователя до 5 подписок.
- Фоновая задача в том же процессе раз в `MONITOR_INTERVAL_SECONDS` (по умолчанию 10 минут, со случайным сдвигом до минуты) запрашивает у Reservio слоты всех кортов на 8 дней вперёд, по одному запросу на услугу. Если подписок нет, запросов нет. Если не ответила ни одна услуга, интервал удваивается до часа, а ответ 429 с `Retry-After` соблюдается.
- С 23:50 до 07:50 по Батуми бот не опрашивает Reservio и не пишет. Корт, освободившийся ночью и ещё свободный утром, придёт в первом утреннем цикле.
- Уведомление приходит, только если слот был виден занятым и освободился. Сразу после создания или изменения подписки текущие свободные слоты запоминаются молча. Слот, который просто вошёл в окно бронирования Reservio, тоже не считается освободившимся: бот запоминает для каждой услуги самое позднее время, которое она уже отдавала, и слоты позже него считает новыми, а не освободившимися. Если слот пропал и вернулся меньше чем через 30 минут, это считается колебанием. Слоты, до начала которых меньше 30 минут, не присылаются.
- Если какая-то услуга клуба не ответила, клуб пропускается в этом цикле целиком. Уведомление записывается только после успешной отправки, поэтому при сбое Telegram оно придёт в следующем цикле. Если пользователь заблокировал бота, его подписки удаляются.
- Всё по чату собирается в одно сообщение, не больше 20 времён. Кнопки ведут к обычному экрану слота со ссылками на бронь.
- Монитор ходит в Reservio сам, мимо кэша кнопок: ему нужны свежие данные на все 8 дней. Если упрёмся в лимиты Reservio, смотреть сюда первым делом.
- Сбой одного цикла не останавливает опрос. Если же задача мониторинга упала целиком, бот пишет админам из `ADMIN_IDS` и завершается с кодом 1, чтобы Fly (или `--restart` в Docker) поднял его заново.
- `MONITOR_ENABLED=false` выключает опрос, кнопки подписок при этом остаются.

## Обратная связь

- `/feedback текст` сразу отправляет сообщение. Просто `/feedback` ждёт следующее сообщение 10 минут, подойдёт и скриншот. Фото из альбома пересылаются все, но отдельными сообщениями, служебная строка приходит один раз. Скриншот с подписью `/feedback` сам считается фидбеком. Другие команды ожидание не сбрасывают, но и сами фидбеком не считаются.
- Бот пересылает сообщение всем из `ADMIN_IDS` и отвечает на него служебной строкой: id, @username, имя и язык отправителя. Если у человека скрыта пересылка, профиль открывается только по id. Ожидание хранится в памяти процесса и пропадает при перезапуске.
- Админ должен хотя бы раз открыть бота, иначе Telegram не даст боту ему написать. Если `ADMIN_IDS` пуст или сообщение не доставлено никому, пользователь увидит «не получилось отправить».
- Не больше 5 сообщений в час от одного пользователя. В базу текст не пишется, в `/stats` попадает только счётчик.

## Данные

Статистика и подписки лежат в одной базе SQLite, по умолчанию в файле `data/stats.sqlite3` (переменная `STATS_DB_PATH`).

### Подписки

- Подписка хранит Telegram `chat_id` в открытом виде, иначе уведомление некуда отправить. Ещё в ней язык и условия: день или день недели, часы, клуб, число кортов. Для каждой подписки хранятся времена подходящих слотов, о которых бот уже знает, и когда о них писал.
- Удаление подписки сразу удаляет и эти записи. Подписка на дату удаляется сама в 06:00 после её игрового дня.
- С хешами статистики подписки не связаны.

### Статистика

- Вместо Telegram id хранится хеш с секретной солью, по одной строке на пользователя в день. Соль задаётся переменной `STATS_SALT` и в базу не пишется, поэтому по хешам статистики id не восстановить. Но в той же базе лежат `chat_id` подписок в открытом виде, так что сам файл базы нужно беречь. Без `STATS_SALT` уникальные пользователи не считаются вовсе: бот пишет ошибку в лог, а `/stats` предупреждает об этом. Счётчики действий работают в любом случае. Соль нельзя менять после запуска, иначе те же люди посчитаются заново.
- Действия считаются счётчиками по дням без привязки к пользователям: открыли бота, смотрели день, обновляли, открыли время (с клубом и часом), создали и удалили подписку.
- Команда `/stats` показывает уникальных пользователей за день, 7 и 30 дней, новых за неделю, действия, популярные клубы, часы и языки.
- `/stats` отвечает только пользователям из `ADMIN_IDS`. Пока список пуст, команда подсказывает твой id.

## Деплой на Fly.io

Бот работает через long polling, входящий порт не нужен. База статистики и подписок лежит на постоянном томе `/data`.

```bash
fly launch --no-deploy --copy-config   # один раз
fly volumes create padel_data --size 1 --region fra   # один раз, для статистики
fly secrets set BOT_TOKEN=... ADMIN_IDS=... STATS_SALT=$(openssl rand -hex 32)
fly deploy --ha=false
```

Машина должна быть ровно одна. Две машины с одним токеном получат конфликт long polling в Telegram, том с базой подключается только к одной, а опрос мониторинга на двух машинах удвоил бы запросы к Reservio и уведомления. Если Fly всё же создал вторую, выполни `fly scale count 1`.

Для автодеплоя из GitHub добавь секрет `FLY_API_TOKEN` (`fly tokens create deploy`) и запусти workflow «Deploy to Fly.io».

Альтернатива: любой VPS с Docker.

```bash
docker build -t padel-bot .
docker run -d --restart unless-stopped --env-file .env padel-bot
```
