## Надёжность

- [x] **Монитор может молча остановиться.** Если `Poller.run()` упадёт вне цикла (баг вне
  `run_cycle`), `log_monitor_exit` (`padel_bot/main.py:28`) только пишет в лог —
  уведомления по подпискам прекращаются до ручного рестарта, а бот при этом отвечает как
  обычно. Варианты:
  - перезапускать задачу с паузой (и считать перезапуски, чтобы не крутиться в цикле);
  - ронять процесс (`sys.exit` / отмена главной задачи) — Fly поднимет машину заново;
  - минимум — алерт админам в Telegram, а не только лог.

- [x] **Два независимых потока запросов к Reservio.** Кнопки ходят через кэш
  `AvailabilityService` (TTL 60 с, один день), монитор — напрямую через клиент на 8 дней
  вперёд (`padel_bot/monitoring/poller.py`). Похоже на осознанное решение (монитору нужна
  свежесть по всему горизонту), но при лимитах Reservio это первое место, куда смотреть.
  Решить: оставить и записать как решение в `PLAN_MONITORING.md` — или нет.

## Команды

- [x] **`/days` нет в меню команд.** `/days` — алиас `/start` (оба на `cmd_start`,
  `padel_bot/bot/handlers.py:109-110`, оба считаются как событие `start`), а в меню
  (`COMMAND_KEYS`, `padel_bot/main.py:25`) только `start` с текстом «Выбрать день».
  Решить: добавить `days` в `COMMAND_KEYS` + `cmd_days` в `bot/i18n.py` — или оставить
  `/days` скрытым алиасом и не держать два входа на одно действие.

- [x] **`/stats` в группе.** Групповой обработчик (`padel_bot/bot/handlers.py:239`) отвечает на
  `/stats` предложением написать в личку — то есть показывает всем в группе, что такая
  команда есть. Для админской команды, наверное, лучше молча игнорировать в группе:
  убрать `stats` из списка в `on_group_command`.

## Структура

Все три цикла между пакетами (`bot ↔ monitoring`, `bot ↔ stats`, `config ↔ reservio`) —
не циклы импорта (при импорте ничего не ломается), а признак того, что общие вещи лежат
внутри конкретных блоков. Первые два пункта ниже убирают два цикла из трёх.

- [x] **Общие типы — в общий модуль.**
  - `Lang` / `detect_lang` живут в `bot/i18n.py`, а импортируются из `monitoring/models.py:4`,
    `monitoring/store.py:12`, `stats.py:23` → цикл `bot ↔ stats` и часть `bot ↔ monitoring`.
  - `TZ` в `config.py`, который сам импортирует `reservio.models.Venue` (`config.py:10`) →
    цикл `config ↔ reservio`.
  - Модель «игрового дня» (`current_play_day`, `TimeRange`, `DAY_START`) лежит в
    `reservio/service.py`, а нужна боту, монитору и подпискам.

  Вариант: модуль `padel_bot/domain.py` (или пакет) с `Lang`, `TZ`, игровым днём и
  `Venue`/`CourtSlot` — без зависимостей на остальной код.

- [x] **Монитор зависит от UI.** `monitoring/poller.py:19-20` импортирует
  `render_notification` и `notification_keyboard` из `bot`, а `bot/watch.py` — хранилище из
  `monitoring`. Фоновая логика не должна знать про тексты и клавиатуры. Вариант: монитор
  отдаёт «что отправить» (данные), а рендер передаётся ему при сборке в `main.py` как функция.

- [x] **Приватная функция из чужого модуля.** `monitoring/matcher.py:28` импортирует
  `_dedupe` из `reservio/service.py` (так было в плане `PLAN_MONITORING.md`). Сделать
  публичной (`dedupe`) или перенести в общий модуль вместе с игровым днём.

- [x] **Хранилище подписок импортирует тип из монитора.** `monitoring/store.py:14` берёт
  `CyclePlan` из `matcher.py`, а монитор пользуется хранилищем. Мелочь: тип можно положить
  в `monitoring/models.py`.

- [x] **Общие хелперы хендлеров лежат в `handlers.py`.** `bot/watch.py:15` и
  `bot/feedback.py:23` импортируют `private_router`, `safe_edit` и др. из `bot/handlers.py`.
  Вынести в `bot/common.py`, чтобы `handlers.py` был только про просмотр слотов.
